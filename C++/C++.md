# C++

## 头文件

头文件在C++中主要用于包含函数声明、模板定义、宏定义、常量定义等，使得这些定义可以在多个源文件中共享而不需要重复编写。头文件的主要作用包括：

1. 代码重用：通过包含头文件，可以在不同的源文件中使用相同的函数、模板和常量等。
2. 分离声明和实现：头文件通常包含函数的声明，而实现（定义）则放在源文件中。这有助于分离接口和实现，使得代码更清晰、更易于维护。
3. 条件编译：头文件可以使用预处理器指令（如#ifdef、#ifndef、#define等）来控制代码的编译，实现条件编译。
4. 防止重复包含：通过使用宏和预处理器指令，可以防止头文件被多次包含，避免重复定义错误。

MyMath.h（头文件）:

```
#ifndef MYMATH_H
#define MYMATH_H

int add(int a, int b);

#endif // MYMATH_H
```

MyMath.cpp（源文件）:

```
#include "MyMath.h"

int add(int a, int b) {
    return a + b;
}
```

main.cpp（使用头文件的源文件）:

```
#include "MyMath.h"

int main() {
    int result = add(5, 3);
    return 0;
}
```

在这个例子中，MyMath.h头文件包含了add函数的声明，而MyMath.cpp包含了add函数的定义。main.cpp通过包含MyMath.h来使用add函数。头文件保护（#ifndef、#define、#endif）确保了MyMath.h不会被重复包含。在C++编程中，`#ifndef`、`#define`和`#endif`是预处理器指令，用于防止头文件的内容被多次包含，这是一种常见的头文件保护机制，通常称为“包含保护”或“头文件守卫”。这三个指令结合起来，确保了头文件`KALMAN_FILTER_HPP`的内容在同一个编译单元中只被包含一次。如果头文件被包含多次，第二次包含时预处理器会检测到宏`ARMOR_PROCESSOR__KALMAN_FILTER_HPP_`已经被定义，因此会跳过头文件的内容，避免重复定义。

**宏**是预处理器指令的一种，用于在编译之前替换代码中的文本模式。使用宏可以在编译时展开代码，从而减少重复代码、实现条件编译等。在C++中，宏通常通过`#define`指令定义。

## 命名空间

在C++中，**命名空间（Namespace)** 是一种封装全局标识符（如变量名、函数名、类名等）的机制，用于避免命名冲突。命名空间允许程序员组织代码，使得不同模块或库中的同名标识符可以共存，而不会产生冲突。

### 命名空间的主要特点：

1. **避免命名冲突**：在大型项目中，不同的库或模块可能会定义相同的名称。使用命名空间可以避免这些名称之间的冲突。
2. **代码组织**：命名空间可以按功能或库对代码进行逻辑分组，使得代码更加模块化和易于管理。
3. **作用域限制**：命名空间提供了一种作用域限制，使得在命名空间内部定义的名称不会影响命名空间外部的名称。

### 举例

定义命名空间:

```
namespace MyLibrary {
    void function1() {
        // ...
    }

    int variable1 = 42;
}
```

使用命名空间中定义的函数和变量:

```
MyLibrary::function1();
std::cout << MyLibrary::variable1;
```

可以使用"using namespace 命名空间"来简化::操作,但是在大型项目中这种做法可能导致命名冲突.

```
using namespace MyLibrary;
function1();  // 直接调用
```

C/C++标准库中的标识符定义在std命名空间中.

## 关键字

### const

在函数参数中使用`const`关键字表示该参数在函数内部不能被修改。这为调用者提供了一个保证，即函数不会改变传入参数的值。

### &

在函数传参前面加上&表示该参数不是被复制而是被引用,若不在参数前面加上const关键字,则函数内部对该形参进行的修改会同步给传入的实参.

### using

可以借助typedef关键字理解,但是using用法更加广泛

以下代码表示,为等号右侧的自定义类型赋别名"Func",使其更易于调用

```
using Func = std::function<int(int)>;
```

### explicit

* 增加代码的安全性，避免意外的类型转换。
* 提高代码的清晰度，使得类型转换的意图更加明确。
* 防止编译器在不适当的地方进行隐式类型转换，从而减少错误的可能性。
